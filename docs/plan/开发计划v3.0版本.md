# OneAPI多学校管理系统开发计划v3.0

## 概述

本文档是基于实现方案v3.0版本的开发计划，采用迭代式开发方法，确保每个功能模块实现后都有相应的API测试保障。计划考虑了现有代码的清理和重构工作，以及新功能的实现顺序。

## 当前代码状况评估

根据现有代码分析，目前系统已经按照实现方案v1.0实现了部分功能，主要包括：

1. 已实现的功能：
   - 基本的身份识别中间件（`middleware/smart/identity.go`）
   - 课件平台API客户端（`common/client/courseware.go`）
   - 学科组和老师信息的获取和缓存（`model/smart/subject_info.go`）
   - 扩展日志记录（`model/smart/extended_log.go`）
   - 智能模型选择器（`model/smart/selector.go`）

2. 需要重构或清理的代码：
   - 现有身份识别中间件与v3.0方案不符
   - 缓存实现使用内存缓存而非Redis缓存
   - 扩展日志表结构与v3.0方案不符
   - 没有实现预加载机制

## 风险评估与缓解措施

### 风险1：Redis依赖

**风险**：系统对Redis的依赖可能导致单点故障
**缓解**：实现降级机制，在Redis不可用时回退到API直接调用

### 风险2：课件平台API不可用

**风险**：课件平台API不可用时可能影响系统功能
**缓解**：实现完善的降级逻辑，使用默认分组和模型

### 风险3：数据库迁移风险

**风险**：扩展日志表结构变更可能导致数据丢失
**缓解**：实现数据迁移脚本，确保现有数据安全迁移到新结构
