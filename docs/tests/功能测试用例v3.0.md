# OneAPI系统v3.0功能测试用例

## 文档概述

本文档提供了OneAPI系统v3.0版本的完整功能测试用例，覆盖智能模型选择、多学校费用管理、课件平台集成、费用报表等核心功能模块。测试用例基于需求文档、实现方案和开发计划制定，确保系统功能的完整性和正确性。

## 测试环境要求

### 1.1 基础环境
- **OneAPI系统**：v3.0版本
- **数据库**：MySQL 8.0+
- **缓存**：Redis 6.0+
- **课件平台**：可访问的课件制作平台API
- **Dify系统**：配置好的Dify工作流平台

### 1.2 测试数据准备
- 至少3个学校的测试数据
- 每个学校至少2个学科组
- 每个学科组至少2个老师用户
- 配置好的模型渠道（Deepseek、Qwen、智谱等）
- 课件平台API-KEY和基础URL

## 测试用例分类

### 1. 身份解析与智能模型选择测试
### 2. 多学校费用管理测试
### 3. 课件平台集成测试

## 1. 身份解析与智能模型选择测试

### (通过)测试用例1.1：默认身份解析器功能

**测试目的**：验证默认身份解析器在未配置课件平台时的正常工作

**前置条件**：
- OneAPI系统未配置课件平台集成
- 系统使用默认身份解析器

**测试步骤**：
1. 启动OneAPI系统
2. 发送API请求，不包含X-User-ID头
3. 发送API请求，包含X-User-ID头但未配置课件平台
4. 检查系统日志和响应

**预期结果**：
- 系统正常启动，使用DefaultIdentityResolver
- 请求正常处理，用户组为"default"
- 模型选择使用请求中的原始模型
- 系统日志显示使用默认解析器

**测试数据**：
```bash
# 测试请求1：无用户ID
curl -X POST "http://localhost:3000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxx" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "你好"}]
  }'

# 测试请求2：有用户ID但未配置课件平台
curl -X POST "http://localhost:3000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxx" \
  -H "X-User-ID: teacher_001" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```
