# OneAPI前端工程架构说明与v3.0功能开发建议

## 文档概述

本文档基于对OneAPI项目前端代码的深入分析，详细说明了当前前端工程的技术架构、主题系统设计，以及针对v3.0版本新增功能的开发建议方案。

## 1. 当前前端工程架构分析

### 1.1 项目结构概览

```
web/
├── default/          # 默认主题 (Semantic UI React)
├── berry/           # Berry主题 (Material-UI)
├── air/             # Air主题 (Semi Design)
├── build/           # 构建输出目录
├── build.sh         # 构建脚本
├── README.md        # 主题说明文档
└── THEMES           # 主题列表文件
```

### 1.2 主题系统设计

#### 1.2.1 主题切换机制

OneAPI采用**环境变量配置**的主题切换机制：

1. **配置层面**：
   - 环境变量：`THEME=default|berry|air`
   - 配置文件：`common/config/config.go` 中的 `ValidThemes` 映射
   - 主题列表：`web/THEMES` 文件

2. **路由层面**：
   - 后端路由：`router/web.go` 根据 `config.Theme` 动态加载对应主题
   - 静态文件：`web/build/{theme}/` 目录下的构建产物

3. **构建层面**：
   - 构建脚本：`web/build.sh` 遍历 `THEMES` 文件构建所有主题
   - 输出目录：每个主题构建到 `web/build/{theme}/` 目录

#### 1.2.2 主题切换使用方法

**当前使用方式**：
```bash
# 方式1：环境变量设置
export THEME=berry
./one-api

# 方式2：Docker环境变量
docker run -e THEME=berry one-api

# 方式3：配置文件设置
# 在配置文件中设置 THEME=berry
```

**前端界面切换**：
- **当前状态**：前端界面**没有**提供主题切换功能
- **原因分析**：主题切换完全依赖后端配置，前端无法动态切换

#### 2.4.2 开发规范建议

**代码组织**：
```javascript
// 统一的目录结构
src/
├── pages/              # 页面组件
├── components/         # 通用组件
├── hooks/             # 自定义Hooks
├── utils/             # 工具函数
├── constants/         # 常量定义
├── services/          # API服务
└── styles/            # 样式文件
```

**组件设计原则**：
1. **单一职责**：每个组件只负责一个功能
2. **可复用性**：组件设计要考虑复用
3. **主题适配**：组件要支持多主题
4. **性能优化**：合理使用React.memo和useMemo

**API调用规范**：
```javascript
// 统一的API调用方式
import { API } from 'utils/api';

const useCostReport = () => {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const fetchData = async (params) => {
    try {
      setLoading(true);
      const response = await API.get('/api/cost-report', { params });
      setData(response.data);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  };

  return { data, loading, error, fetchData };
};
```
